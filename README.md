# 公考岗位自动匹配助手

`civil-service-job-matcher` · Codex Skill · Python 3.9+

公考岗位匹配 Codex 技能。输入多个学历、多个专业、培养方式和目标省份后，由 Codex 助手查找并核验官方招录资料，Python 脚本完成档案解析、职位采集、标准化、确定性匹配和结果导出。

**输入学历与专业，获得带官方来源、匹配理由和核验事项的职位清单。** Codex 负责联网发现和政策解读，Python 脚本负责采集、规则计算与导出。

```mermaid
flowchart LR
    A[多学历 · 多专业 · 目标省份] --> B[官方公告与职位表]
    B --> C[专业目录与当年政策]
    C --> D[逐学历路径匹配]
    D --> E[候选 · 待核验 · 排除]
    E --> F[Excel · CSV · JSON · 报告]
```

## 适合做什么

- 省考选岗：按目标省份、年度和批次筛选普通公开招录岗位。
- 多学历、多专业资格检查：不同毕业证、不同专业、主修／辅修／第二学位分别保留，不合并成一条虚假路径。
- 培养方式核查：区分全日制、自考、非全日制、成人教育等；自考不被自动当成全日制，非全日制硕士仍是研究生学历但培养方式不同。
- 学历、学位、专业证书分别判定：只有硕士学位不等于研究生学历，有毕业证也不自动有对应学位。
- 复杂职位重筛：把“本科及以上”“全日制”“专业类别”“党员且男性”等原文转换为带证据的规则。
- 当前资格与未来拿证情景分开运行；历史批次、已截止和已取消职位不混入当前可报清单。

## 助手与脚本的分工

| 环节 | 执行者 | 实际行为 |
|---|---|---|
| 自然语言输入整理 | 助手 | 把多义描述整理为可审计 JSON，保留原文、歧义和未知字段 |
| 固定格式解析 | Python | `civil_service.py profile` 只解析文档规定的固定行格式 |
| 官方资料发现 | 助手 | 实际联网搜索、读取公告／专题／地市入口并核验主办机构 |
| 检索任务清单 | Python | `discover` 只准备分省检索任务，不冒充已经发现岗位 |
| 官方附件采集 | Python | 下载助手核验过的页面和附件，记录 URL、哈希、失败与跳过原因 |
| 当年政策准备 | 助手 | 读取当省当年公告、指南和目录，生成可解释的 `policy.json` |
| 职位标准化 | Python | 解析普通 XLSX／XLS／CSV，保留原表头、sheet、行号、表注和未映射条件 |
| 资格匹配 | Python | 执行三态规则、路径绑定、目录映射、偏好排序和导出 |
| 复杂条款、PDF 表格 | 助手 | 读原文后补 `field_rules`／`policy`；必要时核对 PDF 表格列关系 |

## 输入

聊天文本、JSON 或 `assets/input-form.html` 均可。最小文本格式：

```text
省份：湖南、安徽
学历专业：
- 大专—物流管理（全日制）
- 本科—计算机科学与技术（自考）
- 本科—会计学、法学（全日制）
- 硕士研究生—软件工程（非全日制）
年度：最新已发布
```

以上内容来自 `assets/input-example.txt`，是**虚构的格式示例，不是任何真实用户档案**。不要把它当作用户事实。

- 省份可填大陆 31 个省级行政区名称；未填年度时逐省查询最新已发布常规招录，并展示实际采用年份。
- 学历可重复添加。每条学历分别记录层次、培养方式、毕业状态、毕业日期、学历认可情况；专业再单独记录证书名称、代码、主修／辅修／第二学位性质和对应学位。
- 培养方式和学位未知时保留 `unknown`，不自行补成全日制或“已取得”。未来拿证用独立情景运行。
- 固定行格式由脚本解析；自然语言和多义表达由助手整理 JSON，脚本不会凭空理解任意散文。
- 输入表单完全离线，只导出 `profile.json` 供技能继续处理；表单本身不访问省考网站，也不上传资料。

## 判定规则

每个资格路径严格绑定“一个学历 + 一个专业 + 对应学位”。禁止把本科学历和专科专业拼接，也不把辅修专业自动提升为主修；一条路径失败不排除其他路径。学历或专业列表未确认完整时，已填路径全部失败只能得到 `REVIEW`，不能证明全部路径失败。

三态结果：

- `PASS`：已有官方规则和档案事实足以满足该条件。
- `FAIL`：已有明确原文或规则证明不满足。
- `REVIEW`：档案事实、来源、目录归属或条款解释仍需核验。

A/B/C/D 分类（分类本身只表达资格与偏好；是否在“当前四类”清单中还取决于 `open`、范围和当前官方身份）：

- `A 主攻`：资格匹配，且命中用户偏好；开放且范围内的当前官方岗位进入 A 清单。
- `B 待核验`：资格尚未完全确定，需要补充个人事实或官方解释。
- `C 备选`：资格匹配，但未命中偏好；开放且范围内的当前官方岗位进入 C 清单，偏好不能抵消硬条件。
- `D 排除`：有明确失败依据，不用“还有待核验项”包装成可尝试。

报名状态独立于资格：`open` 才是当前开放；`not_started`、`closed`、`cancelled`、`unknown` 另列。只有日期而无当日具体时刻时，报名首尾日保留 `unknown`。`open` 且范围内的当前官方岗位才进入当前四类统计；历史和取消岗位不能当作当前可报机会。

空白不等于“不限”；“不限全日制”不能被“全日制”关键词误杀；专业类别必须使用当省当年采用的正式目录，不能按相似词推断，也不能跨省借目录。需要招录单位认定的专业归属或资格条件，明确保留为待核验。

## 输出文件

`scripts/match_jobs.py` 的实际内置输出：

```text
report/
├── results.json       # 运行统计、逐职位逐路径规则、待核验项、来源覆盖
├── 岗位匹配.xlsx      # 总览、全部明细、A/B/C/D、历史及其他状态、逐项规则依据
├── 岗位匹配.csv       # 扁平明细，UTF-8 with BOM
└── 匹配报告.md        # 概要、覆盖说明、优先补充项、初筛候选摘要
```

采集阶段另有 `raw/collection.json` 和分省目录下的 `manifest.json`；标准化阶段输出 `jobs.json`。每项判定保留原始字段、来源 URL／哈希和 sheet／行／列或条款位置。仓库不附带任何真实用户生成的匹配结果。

## 2026 年匿名化辅助运行证据

以下数据为 **2026-11-24 匿名化汇总的助手辅助运行证据**，不是仓库内置基准，也不是单条命令的固定产出。候选均指候选岗位记录，不是报名人数或录用结果。

| 来源范围 | 读取职位 | 学历专业通过 | 普通候选待核验 | 其中计算机优先核验 |
|---|---:|---:|---:|---:|
| 湖南全省 | 7,080 | 1,780 | 344 | 140 |
| 安徽省直及 13 市 | 3,028 | 931 | 250 | 123 |
| 合计 | **10,108** | **2,711** | **594** | **263** |

湖南应用了 258 行计划调整，203 个取消职位单列。学历专业通过数包含仍有其他资格障碍的职位；普通候选已做进一步筛选。

这些分层结果来自助手对当次政策的解读和第二阶段筛选，不能由原始脚本一键复现为固定数字。安徽因官方访问失败缺少合肥、亳州、蚌埠，后续地市修订也未全部核对；因此该汇总不能视为两省完整无遗漏覆盖。湖南、安徽 2026 报名均已结束，以上仅是历史证据，不代表当前开放机会。结果不宣称筛选成功率、基准准确率或录取结果。

仓库仅保留通用技能、格式示例和汇总数据；个人档案、原始运行目录及逐人匹配结果不随仓库发布。

## 官方来源与证据

`references/official-source-registry.json` 登记 31 个可输入省份，但只包含两条已核验的历史入口示例，用于理解官方来源形态，**不表示其他省份已预置当年政策**：

- 湖南 2026 公告：<https://www.hxw.gov.cn/content/2026/01/13/14851200.html>，专题 <https://www.hxw.gov.cn/topic/294/>，发布方为中共湖南省委组织部红星网，2026-11-24 核验，仅历史参考。
- 安徽 2026 公告：<https://www.fyxfw.gov.cn/display.php?id=151706>，中共阜阳市委组织部转载安徽省公务员局公告，2026-11-24 核验，仅历史参考；附件不能视为全省覆盖，仍需各地市官方职位表。

新年份必须重新联网检索。搜索结果、培训网站、非官方转载和用户上传文件都不能自动标为官方。每次运行的实际来源写入 `sources.json`、采集台账和结果文件。

## 资料不完整时

- 访问失败写入分省 `failures`，页面上限或跨站待核验写入 `skipped`，缺失材料写入 `missing_kinds`。
- `coverage_confirmed` 只有在核对省直／地市、定向职位、更正、核减和取消之后才可为 `true`。
- `collection.json` 状态为 `partial` 或 `fetch_failed` 时，报告必须说明缺口，不能声称“全省无岗”。
- PDF 可提取文本，扫描件或复杂表格可能标记待 OCR／人工核对；采集器成功下载不等于附件已正确解析。
- 历史、补充录用、已截止和已取消记录单独呈现，不混入当前可报清单。

在 Codex 中直接调用技能并给出目标省份、学历、专业和年度：


## 已知能力边界

- 不是自主爬虫。采集器默认每省最多 20 个 HTML 页面、深度 2，只跟随助手核验过的入口及可识别的官方链接；动态页面和遗漏附件由助手补采。
- 不是全国政策数据库。31 个省级输入名称受支持，但仅湖南、安徽有已核验历史来源示例；其他省份的当年政策必须现场获取，不能根据本仓库推断。
- 不是通用 PDF 表格 OCR。普通 XLSX／XLS／CSV 可自动标准化；PDF 文本和 DOCX／ZIP 可采集提取，扫描 PDF、复杂合并表头或图片表格需助手核对。
- 不支持“所有省份已端到端测试”或“资格 100% 准确”的宣称。实际覆盖取决于当次官方可访问性、材料完整度和政策解释证据。
